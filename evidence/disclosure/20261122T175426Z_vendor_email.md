   findings for triage.
 
   Summary:
   - Registry.register_pure_from_source accepts tier="native_venv", and
     _validate_portable_source applies _WASM_GUEST_STDLIB_MODULES to native
     execution. That allowlist contains os/subprocess/socket/ctypes and similar
     modules, which are neutered in the wasm guest but fully capable in the
     native host subprocess.
   - The native executor runs bundle-supplied source via exec(...) in a real
     Python subprocess with host OS access and no visible container/seccomp/
     namespace isolation.
   - Bundle signatures are detached provenance/integrity checks; executorTier is
     inside signed manifest bytes. JULEP_PURE_NATIVE_DEPS is worker-side operator
     configuration and authorizes pure names, not source hashes.
   - A process-level test using four OS worker processes, two allowlisted
     signers, and one shared artifact store shows fresh workers can resolve and
     invoke different signed implementations under the same granted name; warm
     workers pin name -> source_hash only within the process. I am treating this
     as a supporting deployment-consistency observation, not a second RCE.
 
   Prerequisites and limits:
   - I did not find an unauthenticated or ordinary client-role path to introduce
     executable bundle source.
   - Exploitation appears to require operator-side publication/signing plus a
     worker-side native grant and admin activation where applicable.
   - Proposed CVSS is conditional: 7.2 upper bound with PR:H for default
     operator-controlled publication; 8.8 only if delegated signing or pipeline
     compromise gives an attacker an allowlisted signature path; 6.7 if bundle
     introduction is treated as a local privileged operation. Classification
     depends on the intended contract and deployment model.
 
   Contract ambiguity for triage:

   (if signed)” that must “run fail-closed through its selected tier,” while the
   native-tier docs describe JULEP_PURE_NATIVE_DEPS as “the operator trust
   boundary.” The intended native-tier guarantee should be confirmed during
   triage: either the grant authorizes exact signed source for host execution, or
   native-tier source must still pass tier-appropriate validation.
